# ЯСП — лабораторная № 2, вариант 4: Fraction

**Исполнитель:** Кузнецов Дмитрий Олегович, группа 91.

## Что сдавать

- `lab_module.ixx` — класс `Fraction` и математика.
- `lab_io.ixx` — консольный ввод, проверка данных, файловые операции.
- `main.cpp` — меню, отчёты, подтверждение сохранения.

Это консольное приложение на **C++20 с именованными модулями**. Стандартные контейнеры, `auto`, лямбда-функции и расширения .NET в исходниках не используются. Поля дроби: `int32_t` и `uint32_t`.

## Сборка в Visual Studio 2022 (Windows)

1. Создать проект **Console App (C++)**.
2. В свойствах проекта выбрать стандарт **ISO C++20 (`/std:c++20`)**.
3. Добавить `lab_module.ixx` и `lab_io.ixx` как **C++ Module Interface Unit** (или задать им соответствующий тип элемента в свойствах Visual Studio).
4. Добавить `main.cpp` как обычный C++ исходник.
5. При необходимости отключить предкомпилированные заголовки для `.ixx`, если шаблон проекта их требует (`/Yu`); в этих файлах есть глобальный фрагмент модуля `module;`.
6. Собрать проект **Build → Rebuild Solution**, затем запустить. Модули компилируются в порядке зависимостей: `lab_module` → `lab_io` → `main`.

Старый модуль `lab_module.ixx` из прежнего проекта **нужно заменить**, не добавлять вместе с новым: одноимённые определения вызовут ошибки. Удалить из проекта старый файл, если Visual Studio продолжает его компилировать.

## Вход и выход

- Пункт 1: ввод A и B из консоли, по одной дроби в строке.
- Пункт 2: загрузка двух дробей из файла (одна на строку); можно указывать полный путь.
- Допустимые записи: `5`, `-3/4`, `+1/2`, `2 3`. Знаменатель строго положителен.
- После любого **успешного** действия, в том числе сравнения и вывода A/B, предлагается сохранить показанный текстовый отчёт.
- Чтение и запись принимают полный путь или путь от показанной рабочей папки. Можно вставить путь в кавычках, использовать пробелы, кириллицу и любое расширение.
- Enter в запросе пути возвращает в меню. После ошибки можно ввести другой путь. Создание недостающих папок и перезапись существующего файла требуют подтверждения.
- Программа записывает отчёт во временный файл и только после успешного закрытия заменяет выбранный файл. После сохранения показывает полный путь.
- Входной файл должен быть обычным файлом. UTF-8 BOM в начале файла **не поддерживается** — по согласованному решению обработку маркера не добавляли. Текст с обычными ASCII-цифрами и `/` лучше сохранять как UTF-8 без BOM.

## Согласованные ограничения

- Возведение в **рациональную степень** сохранено: преподаватель требует именно такой вариант. При иррациональном результате или отсутствии вещественного значения операция сообщает об ошибке.
- Арифметика использует предварительное сокращение и проверки переполнения **до** умножения; расширенные встроенные целочисленные типы для промежуточных вычислений не используются.
- При некоторых больших промежуточных значениях операция может сообщить о переполнении, даже если окончательный математический результат представим в полях `Fraction`. Это сознательное упрощение, согласованное для учебной работы.
- Не реализованы побитовые операции и `operator[]`: для дроби нет естественного смысла этих операций.

## Быстрая проверка

1. Пункт 1: A=`1/2`, B=`2/3` → пункт 4, сложение → `7/6`.
2. Пункт 6 → `A < B: true`, затем сохранение `compare.txt` → содержимое файла должно совпасть с выведенным отчётом.
3. Пункт 5: A=`4/9`, показатель=`1/2` → `2/3`; для A=`-8/27`, показатель=`1/3` → `-2/3`.
4. Пункт 7: A=`1/2`, постфиксный инкремент → возвращается `1/2`, после операции `3/2`.
5. Загрузка файла с двумя дробями без перевода строки после второй дроби должна быть успешной.
6. Сохранить отчёт в `Для защиты/сравнение`, подтвердить создание папки и сверить полный путь. При вводе `NUL.txt` программа должна повторить запрос.
7. Если файл `result.txt` уже есть, при ответе `0` на подтверждение он должен остаться неизменным.
8. При загрузке файла с нулевым знаменателем, лишними данными или слишком длинной строкой должна выводиться ошибка, а значения A/B сохраняться.
