# ЯСП: лабораторная № 2, вариант 4

Кузнецов Дмитрий Олегович, группа 91. Класс `Fraction` для обыкновенных дробей.

## Запуск

Открыть `lab_02.slnx` в Visual Studio с установленными средствами разработки C++, выбрать `Debug | x64` и запустить. Проект использует C++20: он нужен для модуля, как в первой лабораторной.

- `main.cpp` — повторяющееся меню, выбор операции и обработка ошибок.
- `Module.ixx` — класс, операции и функции ввода-вывода; импортируется как `lab_module`.
- `examples` — файлы для загрузки через пункт 2 меню.

Начальные значения `A` и `B` — `0/1`. Результат арифметики и степени хранится отдельно; сами `A` и `B` меняются при вводе, загрузке и `++`. После нового ввода или загрузки старый результат скрывается. При ошибке прежние корректные значения сохраняются. Конец консольного ввода завершает программу.

## Ввод и файлы

Дробь вводится двумя целыми числами через пробел: **числитель знаменатель**. Для `A` и `B` используются отдельные строки. Например:

```text
6 8
-2 3
```

Получатся `A = 3/4`, `B = -2/3`. Запись `3/4` предназначена для показа на экране, а не для ввода.

После выбора загрузки или сохранения программа запрашивает имя файла. Допускаются путь и пробелы, окружающие кавычки необязательны. Относительный путь отсчитывается от папки проекта при запуске из Visual Studio, а при запуске из терминала — от текущей рабочей папки. Пример: `examples\ordinary.txt`.

Для загрузки нужны ровно две строки с дробями; после них разрешены только пробельные символы. Файл с ошибкой или лишними данными не меняет `A` и `B`.

Пункт 8 позволяет сохранить:

- **A и B** — две строки, этот файл можно загрузить обратно;
- **последний результат** — одну строку, для чтения результата человеком.

Выбранный файл создаётся или **перезаписывается**. Папки программа не создаёт. Имя ограничено 511 символами, строка числового ввода — 127 символами; более длинный ввод отклоняется целиком.

| Файл | Что проверить |
| --- | --- |
| `ordinary.txt` | Сокращение, отрицательная дробь, четыре арифметические операции |
| `equal.txt` | `2/4 == 1/2`, все шесть сравнений |
| `zero.txt` | Нормализация `0/15` в `0/1`; для проверки деления на ноль затем ввести `B = 0 1` |
| `limits.txt` | Минимальный числитель и максимальный знаменатель, точные сравнения |
| `cross_cancel.txt` | Произведение равно `1/1` благодаря сокращению до умножения |
| `invalid.txt` | Нулевой знаменатель во второй строке; прежние данные должны сохраниться |

## Требования и ограничения

- Два закрытых поля: `int32_t` и `uint32_t`. Это обычная 32-битная модель без искусственного ограничения дробей до 8 или 16 бит. Знаменатель положителен, дробь сокращена, ноль всегда `0/1`.
- Реализованы внешние `+`, `-`, `*`, `/` и все шесть сравнений; `friend` получают только операции, которым нужны закрытые поля. Неизменяющие методы имеют `const`, аргументы-дроби передаются по `const`-ссылке.
- `power` принимает положительный натуральный показатель. Нулевая и отрицательная степени не входят в выбранное условие; ноль отклоняется.
- `++A` возвращает изменённую дробь, `A++` — прежнюю; оба прибавляют целую единицу. В меню показываются возвращённое значение и состояние объекта.
- `to_string` записывает представление `числитель/знаменатель` в массив символов. Функции консольного и файлового ввода используют общий разбор дроби. Вывод на экран и в файл доступен из меню.
- Нет `auto`, лямбд, динамических контейнеров, `std::string`, вещественной арифметики или расширения чисел до 64 бит. Для текстового ввода и преобразования чисел используются стандартные `from_chars` и `to_chars` из `<charconv>`.
- Побитовые операции над дробями и индексация `[]` не вводятся: в условии они нужны только при наличии смысла для конкретного класса.
- Переполнение проверяется **до** сложения и умножения. Умножение и деление предварительно сокращаются крест-накрест; сравнение выполняется через целые части и остатки, без перекрёстного произведения. Минимальное отрицательное число обрабатывается без его прямого отрицания.
- **Ограничение сложения и вычитания:** если промежуточное произведение или сумма модулей не помещаются в `uint32_t`, операция отклоняется даже тогда, когда дальнейшее сокращение могло бы дать представимую дробь. Например, `2147483647/2 + (-2147483647/3)` отклоняется, хотя итог `2147483647/6` представим. Это сознательный отказ от отдельной арифметики для составных чисел: программа выдаёт ошибку, а не неверное значение. Случаи, проходящие эти проверки, считаются точно.

Проверено: сборки MSVC в режимах Debug и Release для x64, 16 088 случаев арифметики и сравнений с независимым расчётом через рациональные числа, 52 сценария меню и файлового ввода-вывода, 13 дополнительных проверок повреждённых строк и ошибок консольного потока.
