# Подготовка к защите — ЯСП, лабораторная № 2, вариант 4

Код для разбора: `lab_module.ixx`, `lab_io.ixx`, `main.cpp` из **того же комплекта**. Нельзя готовиться по старому единому модулю: после рефакторинга расположение функций и меню поменялись.

## 0. Объяснение за минуту

> Я реализовал собственный числовой тип `Fraction`, представляющий обыкновенную дробь через знаковый числитель `int32_t` и беззнаковый положительный знаменатель `uint32_t`. Конструктор приводит дробь к несократимому виду посредством алгоритма Евклида. Арифметические операторы и сравнения перегружены для удобной работы с объектами. Для предупреждения переполнений применяются проверки до опасных операций и сокращения множителей. Рациональную степень вычисляю только тогда, когда результат можно точно представить рациональной дробью. Ввод обрабатывается построчно, поэтому неверное значение не оставляет лишнего текста в потоке. Программа умеет читать две дроби из файла и формировать отчёты; после любого успешного действия отчёт можно сохранить по указанному пути. При выборе существующего файла программа спрашивает разрешение на перезапись.

## 1. Организация проекта и соответствие условиям

Это **C++20-модули**, не старые заголовочные файлы. `export module lab_module;` объявляет модуль; `export` перед классом или функцией делает объявления доступными импортирующим единицам; `import lab_module;` импортирует его в другой файл. Строка `module;` в начале `.ixx` открывает *глобальный фрагмент модуля* для стандартных `#include` и Windows API. `lab_io` импортирует математический модуль, а `main.cpp` импортирует оба.

Условие: арифметика `+ - * /`, сравнения, рациональная степень по требованию преподавателя, префиксный и постфиксный `++`, ввод и вывод в консоль и файл, строковое представление, меню до выхода. Битовые операции и индексирование `[]` для рационального числа не имеют естественной семантики; их нет. Контейнеры `std::vector` и `std::list`, `auto` и лямбды в коде не используются.

## 2. `lab_module.ixx`: объяснение по функциям

### Поля и инварианты

```cpp
std::int32_t numerator;
std::uint32_t denominator;
```

- `numerator` — числитель со знаком, диапазон `[-2147483648; 2147483647]`.
- `denominator` — беззнаковый знаменатель, диапазон `[1; 4294967295]` (ноль запрещён).
- Дробь всегда хранится **сокращённой**; `0/10` преобразуется в `0/1`.
- Инвариант класса — утверждение, которое истинно после любого успешно завершённого метода, меняющего объект.
- Поля не объявлены `public`, чтобы пользователь не мог записать `denominator = 0` или сделать дробь несократимой вручную.

### Конструктор `Fraction(n, d)`

```cpp
Fraction(std::int32_t n = 0, std::uint32_t d = 1);
```

Аргументы по умолчанию позволяют писать `Fraction a;` (создать ноль), `Fraction a{5};` (целое 5) и `Fraction a{6,8};` (сократится до `3/4`). Список инициализации `: numerator{0}, denominator{1}` сразу устанавливает допустимое начальное состояние. `d == 0` вызывает `std::invalid_argument`. Если числитель равен нулю, сохраняется представление `0/1`. Иначе вычисляется НОД модулей и сокращаются оба числа. Особо обрабатывается `INT32_MIN` — число `-2147483648`, положительный модуль которого не помещается в `int32_t`.

### `magnitude(value)` — модуль `int32_t` без переполнения

```cpp
if (value < 0)
    return static_cast<std::uint32_t>(-(value + 1)) + 1;
```

Почему не `-value`? У `INT32_MIN` нет положительного аналога в `int32_t`; прямое отрицание переполняет знаковый тип. Здесь сначала прибавляем 1, меняем знак безопасного значения, затем возвращаем единицу уже в `uint32_t`.

### `gcd(a, b)` — алгоритм Евклида

Пока `b != 0`, вычисляется `remainder = a % b`, затем `a = b; b = remainder;`. На завершении `a` содержит НОД. Например `gcd(18,12) → gcd(12,6) → gcd(6,0) = 6`. НОД нужен для сокращения и уменьшения промежуточных множителей.

### `multiply(a, b)` — предварительная проверка переполнения

```cpp
if (b != 0 && a > std::numeric_limits<std::uint32_t>::max() / b)
    throw std::overflow_error(...);
return a * b;
```

Умножение не выполняется до проверки: `a*b` может переполниться уже **во время вычисления**, независимо от наличия `result`. Сравнение через `UINT32_MAX / b` безопасно при `b != 0`. Исключение предотвращает неверный результат. Для некоторых сложений временный результат оказывается слишком велик, хотя после сокращения результат мог бы поместиться: это согласованное ограничение реализации.

### `from_parts(n,d,negative)`

Закрытая **статическая** фабричная функция класса: принимает отдельно модуль числителя, знаменатель и знак. Проверяет `d != 0`, сокращает по НОД, проверяет, что сокращённый числитель представим в `int32_t`, затем создаёт `Fraction`. Допускает модуль `2147483648` только для отрицательной дроби (`INT32_MIN`). Этот метод не зависит от конкретного объекта, поэтому `static`.

### `add(a,b,subtract)`, `operator+`, `operator-`

Для `a/b ± c/d` вычисляется `common = gcd(b,d)`, затем два числительных с приведением к общему знаменателю. Вместо повторения алгоритма `operator+` передаёт `false`, `operator-` — `true`.

1. `left = abs(a.numerator) * (b.denominator / common)` — модуль первого слагаемого.
2. `right = abs(b.numerator) * (a.denominator / common)` — модуль второго.
3. Для вычитания меняем знак второго слагаемого логически: `right_negative = (b.numerator < 0) != subtract`.
4. Если знаки совпадают — складываем модули; иначе вычитаем меньший модуль из большего и берём знак большего.
5. Если результат равен 0 — возвращаем `Fraction{}`.
6. Сокращаем и создаём результирующий объект с помощью `from_parts`.

Пример: `1/2 + 1/3 = 5/6`; `1/2 - 1/3 = 1/6`. При подозрении на переполнение функция выдаёт исключение до вычисления произведения.

### `operator*`, `operator/`

Умножение использует **перекрёстное сокращение**: НОД числителя первой дроби со знаменателем второй и наоборот. После сокращения вычисляет произведения через `multiply`. Это уменьшает вероятность переполнения. Знак результата — XOR знаков (`!=`). Умножение на 0 сразу возвращает `Fraction{}`.

Деление сначала проверяет `b.numerator == 0` (деление на ноль). Далее вычисляет `(a/b)/(c/d) = (a*d)/(b*c)`, но сначала сокращает числители и знаменатели через НОД; нулевой делимый даёт 0. Важный случай: при отрицательном делителе знак учитывается отдельно, знаменатель остаётся положительным.

### Операторы сравнения

- `operator==`: сравнивает пару полей напрямую, **потому что дроби всегда сокращены**.
- `operator!=`: отрицание равенства.
- `operator<`: учитывает знаки, а затем сравнивает дроби через целые частные и остатки (вариант алгоритма цепных дробей); не умножает крест-накрест большие числа.
- `operator>`: `return b < a;`.
- `operator<=`: `return !(b < a);`.
- `operator>=`: `return !(a < b);`.

Зачем такая сложная проверка `<`? Обычное `a.numerator * b.denominator < b.numerator * a.denominator` может переполнить целочисленный тип. В `operator<` вместо этого сопоставляются целые части, остатки, затем обратные дроби. При переходе к обратным дробям направление сравнения меняется (`reverse = !reverse`).

### `exact_root(value, degree)` и `power(exponent)`

`exact_root` ищет **точный целочисленный корень** бинарным поиском. Для кандидата `middle` вычисляется `middle^degree` только с проверками против переполнения (деление `value / middle` перед умножением). Если точного корня нет, бросает `std::domain_error`. Большая степень `degree>=32` при `value>1` не может иметь точного целого корня в 32-битном диапазоне.

Степень представлена дробью `p/q`: сначала извлекается точный `q`-й корень из числителя и знаменателя основания, затем возводится в целую степень `|p|` методом **двоичного возведения в степень**. Если `p<0`, основание заменяется обратной дробью; если исходное основание отрицательное и `q` чётно, нет вещественного значения. Чётность `p` определяет знак отрицательного основания.

Проверки: `0^0` — ошибка; `0` в отрицательной степени — ошибка; отрицательное основание в степени с чётным знаменателем — ошибка; иррациональный результат не представляется классом и отклоняется. `4/9` в степени `1/2` → `2/3`; `-8/27` в степени `1/3` → `-2/3`; `2` в степени `1/2` → ошибка (иррациональный результат).

### `++` — два разных оператора

```cpp
Fraction& Fraction::operator++() { *this = *this + Fraction{1}; return *this; }
Fraction Fraction::operator++(int) { Fraction previous{*this}; ++(*this); return previous; }
```

Префикс `++a` прибавляет целую единицу и возвращает **ссылку на изменённый объект**. Постфикс `a++` сначала запоминает старую дробь, вызывает префикс, возвращает **старую копию**. Неиспользуемый параметр `int` — способ различить сигнатуру постфиксного оператора, он не означает прибавления `int`.

### `to_string(text, capacity) const`

Преобразует дробь в C-строку, переданный буфер заполняется через `std::to_chars`. Если знаменатель равен 1, выводит только целое, иначе `числитель/знаменатель`. Проверяет границы буфера и добавляет `\0`. Метод помечен `const`, поскольку не меняет дробь. `std::to_chars` не использует локаль; строки предназначены для ASCII-чисел.

## 3. `lab_io.ixx`: объяснение по функциям

### `read_line(input, text, capacity)`

Это основной защитный механизм ввода. `getline` считывает **всю строку**, а не один токен. `input.gcount()` сообщает, сколько символов извлечено, включая `\n`, когда он встретился. Если строка слишком длинная, остаток отбрасывается до следующего `\n`, и выбрасывается `invalid_argument` — следующая попытка ввода начинается с новой строки, а не с середины старой.

Когда файл заканчивается **без последнего перевода строки**, `getline` выставляет `eofbit`. Если до этого было извлечено ненулевое число символов, функция всё равно принимает эту последнюю строку. Если извлечено 0 символов, возвращает `false` (конец ввода). `strlen(text)` сопоставляется с количеством фактически прочитанных байтов, чтобы отклонить скрытый `\0` внутри строки. `input.bad()` означает серьёзную ошибку чтения — её не трактуем как простой неправильный формат.

### `skip_spaces(text)`

Сдвигает локальный указатель по пробельным символам через `std::isspace`, **не перемещая данные в памяти**. Приведение `unsigned char` нужно, чтобы корректно вызывать `isspace` при символах с установленным старшим битом.

### `read_fraction(input, value)`

1. Получает одну строку `read_line`, а при окончании потока возвращает `false`.
2. Пропускает начальные пробелы; при необходимости разрешает `+` перед цифрами.
3. `std::from_chars(start,end,numerator)` преобразует целочисленное значение *без чтения из потока и без изменения локали*. При невозможном представлении `int32_t` возвращает код ошибки.
4. Если строка на этом закончилась — это целое `n/1`.
5. Иначе нужен разделитель `/` или пробел между числителем и знаменателем.
6. Считывает положительный `uint32_t`-знаменатель, требует `d != 0` и отсутствие лишнего текста.
7. Только **после полной проверки** присваивает `value = Fraction{n,d}`.

Форматы: `5`, `-3/4`, `+1/2`, `2 3`; ошибки: `abc`, `1/0`, `1//2`, `1/2/3`, `2147483648/1`, `1/-2`, пустая строка. Сохранение предыдущего значения при ошибке обеспечено тем, что присваивание находится в самом конце.

### `read_choice(prompt, value, min, max)`

Бесконечный цикл с запросом номера меню. Принимает **одну цифру**, окружённую пробелами, и проверяет диапазон. В нашем меню варианты `0..7`, `0..4` и `0..1`, поэтому одной цифры достаточно. Если строка слишком длинная или содержит неверный символ, выводит пояснение и повторяет попытку. При EOF возвращает `false`.

### `read_fraction_from_console(...)`, `read_from_console(a,b)`

Первая функция циклически запрашивает **одну** дробь до успеха. Вторая читает A и B в **временные локальные объекты** `first`, `second`, и только затем заменяет оба исходных. Поэтому при ошибке или прекращении ввода между двумя объектами старые A и B не меняются.

### Выбор пути

`read_path` показывает рабочую папку и принимает относительный или полный путь. Парные кавычки можно оставить при вставке из Проводника. Пустая строка отменяет операцию. `load_pair` повторяет запрос после ошибки чтения.

### `load_from_file(a,b,name)`

- Проверяет `std::filesystem::is_regular_file` — чтобы открывался обычный файл, а не каталог/устройство.
- Читает ровно две строки-дроби во временные `first`, `second`.
- `file >> std::ws` пропускает оставшиеся пробелы и переводы строк; если остался третий токен, это ошибка избыточных данных.
- Присваивает A и B **только после полной проверки файла**, что защищает от частичной замены при ошибке.

### Сохранение отчёта

`save_report` спрашивает путь и при необходимости предлагает создать папки или заменить существующий файл. `save_to_file` записывает показанный текст во временный файл в выбранной папке. После успешного закрытия файла программа перемещает его на место назначения. Если запись или замена завершилась ошибкой, пользователь может выбрать другой путь для того же отчёта.

## 4. `main.cpp`: как работает управление

1. `Fraction a,b;` — две дроби с нулевым начальным значением; программа живёт в `while(true)` до выбора `0` или завершения ввода.
2. `read_choice` получает номер меню; если EOF или `0`, завершаем.
3. `char output[512]{}` — **единственный буфер отчёта текущей операции**, без `last_output`; `first`, `second`, `answer` — маленькие временные буферы форматирования дробей.
4. `switch(choice)` выполняет действие: 1 — консольный ввод; 2 — загрузка; 3 — показать; 4 — арифметика; 5 — рациональная степень; 6 — логические сравнения; 7 — инкремент.
5. Результат операции сериализуется через `std::snprintf`; в `case 6` логические значения преобразуются в `"true"` и `"false"` тернарным оператором.
6. При вводе/загрузке/показе (`choice` от 1 до 3) отчёт формируется после `switch` по новым значениям A/B.
7. После успешной операции `std::cout << output;`, затем `Save this report?` и при согласии — чтение безопасного имени файла.
8. Если файл существует, дополнительный `Overwrite?`; при отказе файл не трогается.
9. Внешний `catch(const std::exception& error)` отображает ошибки арифметики/ввода, после чего меню повторяется; `std::cin.bad()` рассматривается как невосстановимая ошибка ввода.

Обрати внимание: `std::snprintf` **записывает отформатированный текст в буфер**, а не печатает на экран. `std::cout << output` выводит его позднее. Это позволяет сохранить **тот же текст**, который видел пользователь, независимо от типа результата (`Fraction` или `bool`).

### Почему здесь тернарный оператор уместен

```cpp
Fraction& selected{ object == 1 ? a : b };
a == b ? "true" : "false";
```

Оба выражения выполняют простой выбор одного из двух значений. Использование `?:` уместно для краткости. Для сложных ветвлений, содержащих повторные проверки и несколько действий, в программе оставлены `if`/`switch`.

## 5. Вопросы преподавателя: тренировка

1. **Почему класс, а не две отдельные переменные?** — класс поддерживает инварианты и объединяет связанные операции.
2. **Зачем `private`?** — не дать записать нулевой знаменатель или нарушить сокращённую форму извне.
3. **Для чего `uint32_t`?** — неотрицательный знаменатель с известной разрядностью; ноль отдельно запрещён.
4. **Почему `Fraction{}` означает `0/1`?** — аргументы конструктора по умолчанию, каноническая форма нуля.
5. **Почему не `abs(INT32_MIN)`?** — положительное значение отсутствует в `int32_t`; используем `magnitude`.
6. **Что такое НОД?** — наибольший общий делитель двух чисел, используемый для сокращения.
7. **Почему `gcd` всегда завершается?** — второй аргумент заменяется неотрицательным остатком, меньшим предыдущего ненулевого делителя.
8. **Что делает `from_parts`?** — безопасное создание сокращённого результата из модуля числителя, знаменателя и знака.
9. **Зачем `friend`?** — внешним операторам нужен доступ к закрытым полям; это точечное разрешение.
10. **Почему `operator+` внешняя функция?** — не изменяет ни один аргумент; симметричная бинарная операция.
11. **Почему делаем перекрёстное сокращение перед умножением?** — уменьшаем промежуточные значения и вероятность переполнения.
12. **Почему нельзя сначала умножить, потом сравнить с максимумом?** — переполнение уже произошло при вычислении выражения.
13. **Почему при переполнении бросаем исключение?** — безопасно прекращаем операцию, не выдавая неверный результат.
14. **Гарантируется ли вычисление любого представимого результата?** — нет; промежуточное переполнение иногда вызывает консервативный отказ. Это согласованное ограничение.
15. **Почему равенство — сравнение полей?** — все дроби нормализованы и имеют единственную каноническую форму.
16. **Почему `<` реализовано не через `a*d < c*b`?** — перекрёстные произведения могут переполниться.
17. **Что делает `reverse` в сравнении?** — меняет направление сравнения при переходе к обратным дробям.
18. **Что такое точный корень?** — целое `r` такое, что `r^q = value`; приблизительный `double` не используется.
19. **Почему рациональная степень иногда отклоняется?** — не все такие степени имеют рациональный результат, а класс хранит только точные рациональные числа.
20. **Что будет при `0^0`?** — `domain_error`, поскольку такой случай явно не определён реализацией.
21. **В чём различие `++x` и `x++`?** — первый возвращает изменённый объект по ссылке, второй — прежнюю копию по значению.
22. **Что означает `const` после метода?** — метод не изменяет поля данного объекта.
23. **Что такое `const Fraction&`?** — ссылка на дробь без копирования и без права её изменять через эту ссылку.
24. **Зачем `export module` и `import`?** — разделение интерфейсов в C++20-модульной системе, не `#include` пользовательского заголовка.
25. **Чем `from_chars` отличается от `cin >> n`?** — преобразует уже считанную строку с точной проверкой конечного указателя, не оставляет недочитанный текст в потоке.
26. **Зачем полностью читать строку?** — некорректный ввод не загрязняет следующий запрос; можно обнаружить лишние символы и превышение длины.
27. **Что такое EOF?** — конец входного потока; `read_line` отличает отсутствие очередной строки от ошибочного содержимого.
28. **Что происходит с последней строкой без `\n`?** — она принимается, если были извлечены символы; `eofbit` не означает, что эта строка пуста.
29. **Почему считываем A и B во временные переменные?** — исключаем частичное изменение состояния при ошибке второй дроби.
30. **Откуда считается относительный путь?** От рабочей папки, которую программа показывает перед вводом пути.
31. **Почему `CON.txt` нельзя?** — Windows трактует такие имена как устройства, а не обычные файлы.
32. **Чем `symlink` отличается от `hard link`?** — первая ссылка перенаправляет имя на путь, жёсткая ссылка является дополнительным именем того же файла; проверяем оба случая.
33. **Зачем спрашивать подтверждение перезаписи?** — пользователь не должен случайно потерять предыдущий отчёт.
34. **Как сохранить сравнения, если они возвращают `bool`, а не `Fraction`?** — все результаты формируются в едином текстовом буфере `output`.
35. **Для чего `snprintf`?** — безопасное форматирование строки в буфер заданной ёмкости.
36. **Может ли программа сохранить результат неудачной операции?** — нет; `throw` передаёт управление в `catch` до общего блока вывода/сохранения.
37. **Для чего исключения `invalid_argument`, `domain_error`, `overflow_error`?** — разные категории ошибок: формат/аргумент, математическая область определения и целочисленный диапазон.
38. **Почему нет `vector` или `auto`?** — это прямое ограничение учебного задания.
39. **Почему `save_to_file` принимает готовый отчёт?** — файловая функция не зависит от типа операции и может сохранять и дроби, и сравнения.
40. **Какая сборка проверена?** MSVC, Windows, Debug x64.

## 6. Набор обязательных проверок перед единственной защитой

| Действие | Ожидаемое поведение |
|---|---|
| A=`1/2`, B=`2/3`, сложение | `7/6` |
| A=`1/2`, B=`2/3`, сравнения | `A < B: true`; отчёт можно сохранить |
| A=`4/9`, степень `1/2` | `2/3` |
| A=`-8/27`, степень `1/3` | `-2/3` |
| A=`2`, степень `1/2` | ошибка: иррациональный результат |
| A=`0`, степень `0` | ошибка `0^0` |
| A=`1/2`, постфиксный `++` | Returned=`1/2`, после=`3/2` |
| B=`0`, деление A/B | ошибка, значения A/B сохраняются |
| Ввод `abc`, `1/0`, `1//2`, строка длинее буфера | сообщение об ошибке, запрос повторяется |
| `Examples/valid_without_final_newline.txt` | файл читается успешно |
| `Examples/invalid_zero_denominator.txt`, `invalid_extra_data.txt` | ошибка, A/B не меняются |
| Ввести `../result.txt` | Сохранение в родительской папке при наличии прав записи |
| Ввести `CON.txt`, `COM1.txt`, `NUL.txt` на сохранение | отказ как имени устройства |
| Попытка записи в каталог, символьную ссылку, файл с несколькими жёсткими ссылками | отказ |
| Существующий обычный `result.txt` + ответ «нет» | исходный файл не изменяется |
| Существующий обычный `result.txt` + подтверждение | старый отчёт заменяется новым |
| EOF посреди ввода | корректное завершение, без зацикливания |
| Отсутствуют права записи или кончилось место | понятная ошибка, без ложного сообщения об успехе |


## 7. Что важно повторить перед защитой

1. Инвариант дроби, конструктор, `gcd`, `magnitude`.
2. Проверка переполнения **до** умножения, перекрёстное сокращение.
3. Арифметика и сравнение без опасных произведений.
4. Рациональная степень: точный корень + двоичное возведение в степень.
5. `getline` / `gcount` / `eof` / `from_chars` и полная проверка формата.
6. Имя выходного файла, отличие каталога `.exe` от рабочей директории.
7. `snprintf` → `output` → `cout` → подтверждение → `save_to_file`.

**Главная учебная задача** — уметь объяснить не только, что делает каждая функция, но и что будет, если удалить конкретную проверку.
