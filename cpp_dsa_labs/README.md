# Среда для СДиА

Открыть `cpp_dsa_labs.slnx` в Visual Studio 2026 с компонентами разработки на C++. В одном решении три проекта:

| Проект | Назначение |
| --- | --- |
| `flist` | Общая статическая библиотека `flist::FLIST`, список со служебной головой |
| `lab_01` | Лабораторная № 1, задание № 15: перенос первой группы нечётных |
| `homework` | Отдельная программа для ДЗ; семь рекурсивных операций над списком |

Для запуска выбрать `Debug` или `Release`, платформу `x64`, нажать правой кнопкой на `lab_01` или `homework` → **Назначить запускаемым проектом**, затем **Ctrl+F5**. `flist` — библиотека, отдельно не запускается. Есть и отдельные решения `lab_01/lab_01.slnx` и `homework/homework.slnx`.

Рабочая папка каждой программы — папка её проекта. Лабораторная читает `lab_01/input.txt` и пишет `lab_01/output.txt`; домашняя работа читает `homework/data.txt` и выводит результат в консоль. При запуске из терминала сначала перейти в соответствующую папку.

## Общая библиотека

В рабочих файлах подключать `#include "FLIST.h"`, создавать `flist::FLIST list` и пользоваться `flist::TInfo`, `flist::ptrNODE`. `get_head()` возвращает служебный узел, первый элемент — `get_head()->next`. Не объявлять вторую глобальную структуру `NODE`: это другой, несовместимый тип.

Оба проекта ссылаются на `flist/flist.vcxproj`; общие настройки и путь заголовков находятся в `dsa_common.props`. Библиотека собирается автоматически. Не добавлять `FLIST.cpp` повторно в приложение: реализация уже находится в подключаемой библиотеке. Все новые сборки и промежуточные файлы находятся в игнорируемой папке `build/`.

Для новой лабораторной или ДЗ создать консольный проект C++, импортировать `../dsa_common.props` (путь зависит от вложенности) и добавить **Ссылку на проект → flist**. Функции конкретного задания хранить в его проекте, общие операции — в библиотеке.

## Проверка сборки

Из Developer PowerShell for Visual Studio:

```powershell
MSBuild.exe cpp_dsa_labs.slnx /m:2 /nr:false /t:Build /p:Configuration=Debug /p:Platform=x64
MSBuild.exe cpp_dsa_labs.slnx /m:2 /nr:false /t:Build /p:Configuration=Release /p:Platform=x64
```

Регрессионные проверки библиотеки и рекурсивного ДЗ: `tests/flist_tests.cpp`. Запускать из Developer PowerShell, находясь в `cpp_dsa_labs`:

```powershell
New-Item -ItemType Directory -Path build/tests -Force
cl.exe /nologo /std:c++20 /EHsc /W4 /utf-8 /fsanitize=address /Zi /Iflist /Ihomework tests/flist_tests.cpp flist/FLIST.cpp homework/recursive_tasks.cpp /Fobuild/tests/ /Febuild/tests/flist_tests.exe /Fdbuild/tests/flist_tests.pdb /link /INCREMENTAL:NO
./build/tests/flist_tests.exe
```

Проверочные входные файлы размещать в `build/`, не заменять рабочие `input.txt` и `data.txt` ради проверки.

После сборки обеих конфигураций файловые сценарии приложений можно проверить командой `python tests/check_scenarios.py`. Скрипт использует отдельные папки в `build/scenarios` и проверяет неизменность рабочих входных и выходных файлов.
